# loom v1.6.0 release plan

Status: work in progress, 2026-11-20. Nothing here is a production or safety
claim. Scope lives in rivet (`safety/requirements/verification.yaml`, items with
`release: v1.6.0`); this page explains it.

The plan is measured against the PulseEngine North Star ("A safety-critical
product team can take a WebAssembly component from architecture model to signed
code running on a microcontroller, with evidence an assessor can re-check,
using open tools only"). loom's axis is O3, "Every verified claim is backed":
each public claim that something is verified or proved maps to a CI check that
can fail.

## What the bets do and do not move

The O3 indicator counts "proof-carrying repositories whose proof check, with a
kernel axiom audit and a trust-escape ledger, is a required check". loom is not
listed as a product in the North Star file, and whether a tool repository is
counted is not decided. Every bet below therefore **serves the O3 summary; the
indicator value does not change unless loom is counted**. Whether loom is
counted is an owner decision, tracked outside this plan.

Terms: **proof** is a machine-checked result that can fail (an ordeal `Unsat`
whose certificate loom re-checks, a Rocq kernel check). A Z3 `Unsat` carries no
certificate and is called a **solver verdict**. A **test** executes chosen
inputs. A **measurement** is a number read off a run.

## Baseline (main c717ce6, 2026-11-19)

`loom optimize --stats` over the 30 inputs in the repository (25
`tests/fixtures/*.wat`, 3 `tests/corpus/*.wasm`,
`loom-core/tests/fixtures/issue254-records-fused.wasm`,
`loom-core/tests/fixtures/repro-219/sem.loom.wasm`), all exit 0:

| attempts | proven | kept without proof | rejected and reverted |
|---|---|---|---|
| 7,917 | 7,517 (94.9%) | 35 | 365 |

One attempt is one function after one pass. All 35 kept attempts are in the
meld-fused fixture, reason "body over the solver size threshold"; every other
input is 100% proven. Not counted: modules skipped whole under #196, and
functions left unchanged because an instruction is outside the model. The
default deciding engine is Z3 (`loom-core/src/rule_solver.rs:520`), so all
7,517 are solver verdicts unless run with `LOOM_VERIFY_BACKEND=ordeal`. The
required check "Solver differential" runs `test_verify_all_rules` (38 rewrite
rules), not the validator's per-function obligations
(`.github/workflows/verification-gate.yml`).

## Bet 1: a run states in machine-readable form what was proven, by which engine, and what was taken on trust

Serves O3. Starts first; no other repository involved.

1. `loom optimize --stats-json <file>`: the `--stats` counters as JSON, plus per
   attempt the function index, pass, outcome, deciding engine and reason, and
   the value of every `LOOM_*` budget in effect. No host names or paths.
   `attempts` is counted at entry, independently of the outcome counters.
2. Engine attribution: split proven into `proof` (ordeal, certificate
   re-checked) and `solver_verdict` (Z3). `--stats` prints both.
3. Determinism: run the 30 inputs twice on two machines at one commit; publish
   the per-input differences. A required ratchet waits for this result; if
   wall-clock timeouts make counts unstable, budgets move to deterministic
   limits first.
4. Validator trust ledger `safety/VALIDATOR_TRUST_LEDGER.txt`, generated from
   the code (each `record_kept_unproven` reason, each `LOOM_*` read under
   `loom-core/src/verify*.rs`) plus reviewed structural entries (encoder,
   parser and binary encoder, floats as uninterpreted functions, one NaN payload
   per operation, the #196 whole-module skip and the #345 library/CLI
   difference). Guard rule: the first commit is a one-time disclosure of escapes
   that already exist and says so; after it, entries may only shrink, and a
   deletion must link the change that removed the escape.
5. Coverage ratchet over the 30 inputs (script and baseline committed in the
   repository): fails if `kept_unproven` rises, absolute `proof +
   solver_verdict` falls, output bytes grow, or `attempts` falls. A rise in
   `solver_verdict` alone does not fail it while Z3 is the default.
6. README claims: remove or source every unbacked claim. Today README line 37
   says "consistently achieves 80-95% binary size reduction with 10-30
   microsecond optimization times" and "The entire pipeline is pure Rust"; the
   baseline shows the fused fixture growing 108,701 -> 134,813 bytes in 67 s,
   and the build vendors Z3 (C++).
7. Release: `north-star-input.O3.json` in the shared shape (pulseengine.eu
   #392-#394: facts `proof_check_required`, `axiom_audit`, `ledger`, each with a
   planted control; `ran: false` is a failure; blind spots in `not_measured`),
   written before `SHA256SUMS.txt` so the cosign signature covers it. The facts
   come from runs at the tag commit.

Acceptance, each with a control that must fail with a named message:
- ratchet red on each of its four conditions (four planted regressions, each
  asserting exit 1 and the condition's name in the output);
- ledger check red on a planted reason string and a planted `LOOM_` read
  (exit 1, entry named), and on a deletion without a link;
- each O3 fact turns `ran: false` or `control_failed_as_expected: false` when
  its step is removed (generator tests);
- the claims check red on a planted unbacked sentence of each kind (percent,
  timing, "proven", "pure Rust");
- the ratchet and ledger job is listed in branch protection and has no path
  filter that can skip it.

Kill: the counts are not reproducible across machines on more than the fused
fixture after deterministic budgets; the ratchet then stays advisory and the
bet ships the ledger, the JSON and the published file.

## Gate: ordeal baseline (go/no-go for Bets 2 and 3)

Right after Bet 1 items 1-2: run the 30 inputs with
`LOOM_VERIFY_BACKEND=ordeal` and record the share of attempts ordeal proves
with a re-checked certificate, the reasons it defers, the distribution of
reflected term sizes against `MAX_TERM_NODES` (4096), and wall-clock time.
Published in `docs/measurements/`. #522 measured 2 of 11 seam functions decided
by ordeal on `tests/corpus`, so the share may be low.

- share >= T after #522 and slice 5, where T is set from this measurement
  before any default changes: Bet 2 flips the default;
- share between the kill line (50%) and T: ordeal runs alongside Z3, both are
  reported, the default stays Z3;
- share < 50%: Bet 2 stops at #522 and slice 5, Bet 3 stays an experiment, and
  the release notes say so.

## Bet 2: more verdicts carry a re-checked certificate

Serves O3 (the solver leaves the trusted base for the obligations ordeal
decides). Conditional on the gate.

1. #522: reflect uninterpreted applications as opaque leaves so call and loop
   obligations reach ordeal.
2. TEST-313-TIER2-SLICE5-SYMBOLIC-MEM: symbolic-index memory obligations.
3. If the gate allows: ordeal decides by default; what it defers goes to Z3 and
   is counted `solver_verdict`. `LOOM_VERIFY_BACKEND=z3` remains an opt-out for
   one release.
4. Extend the required solver differential from the 38 rules to the
   validator's obligations over the corpus under `both`.

Acceptance: the `both` job asserts a minimum routed-obligation count (a run
that routes nothing fails) and goes red with the disagreement message on a
test-only ordeal stub that answers `Unsat` for a known inequivalent pair; a
unit test corrupts a certificate step the refutation needs and requires the
verdict to fall back to not proven; the certificate share meets T on the
corpus. The new trusted items (reflection, opaque leaves) enter the ledger in
the same change.

Kill: `both` disagrees on a real obligation (stop, report it to ordeal, keep
Z3); the gate result is under 50%.

## Bet 3 (experiment): exported obligations re-checked by a second solver

Serves O3. Establishes that the formulas loom emits are unsatisfiable to an
independent solver. It does not establish that a formula encodes the two wasm
functions faithfully; the encoder stays a ledger entry.

1. `loom optimize --emit-obligations <dir>`, marked experimental: each
   obligation as SMT-LIB 2 with an index (function, pass, sha256 of input and
   output wasm, engine, budgets).
2. CI: feed the exported obligations to a second solver as a separate process;
   each must answer `unsat`, with a pinned minimum count. Control: an exported
   obligation from a known inequivalent pair must come back `sat`; `unknown`
   and timeouts are reported, never counted as `unsat`.

Cut: re-checking certificates offline and the extra O3 fact wait until
ordeal exposes a serialised certificate and a checker entry point without its
search; that is a request to ordeal, not loom work.

## Bet 4: the falsification statement's behavioral claim is tested by a required execution oracle

Serves O3 (the third bullet of the v1.5.4 falsification statement names no
check today). It is a test, not a proof.

1. Widen the wasmtime differential job to a pinned list of inputs from the
   corpus; the job asserts the list matches, so a deleted input fails.
2. The oracle compares return values, traps, exported globals and linear
   memory. Inconclusive modules are counted, pinned, and may only shrink.
3. Planted-miscompile control: a test-only feature performs one wrong rewrite
   that bypasses the validator; the job requires the oracle to report a
   difference naming that function. A release check fails if any shipped
   artifact is built with the feature.
4. Kept-without-proof functions (from Bet 1's per-attempt identities) are
   executed through an export or listed as unexecuted; the unexecuted count is
   pinned and may only shrink.
5. The job becomes a required check with no skipping path filter, and the
   v1.6.0 falsification statement names it.

Kill: fewer than half the inputs have executable exports (the corpus is the
problem, and the bet becomes building a runnable corpus); any red without a
code change in two weeks keeps it advisory.

## Order

1. Bet 1 items 1-2, then the gate measurement.
2. Bet 1 items 3-6 and Bet 4 in parallel.
3. Bet 2 per the gate; Bet 3 experiment.
4. At the tag: Bet 1 item 7 and the falsification statement.

A release with Bets 1 and 4 alone is worth cutting.

## Out of scope for v1.6.0

- Removing Z3 (TEST-313-EXIT-Z3-REMOVED): the validator's encoder builds Z3
  terms and ordeal receives a reflection of them, so removal needs a neutral
  term builder. Moves to v1.7.0.
- Float obligations (TEST-313-TIER2-SLICE6-FLOATS) and the aarch64 Linux
  release target: move to v1.7.0.
- O5 (loom as a signed WASI component under kiln): kiln does not yet run a
  Rust wasip2 CLI (kiln #480, #687), and the wasm build of loom has no
  validator until Z3 is gone.
- O1, O2, O4: no loom bet moves those indicators this release. loom's
  per-function wasm-to-wasm share must not be quoted as an O1 number.
- #300 (refinement relation), #523 (LICM proof), #347 and #457 (meld seam),
  #231/#240/#144 (facts to synth), #239/#303/#515 (size). #347 should lead the
  following release.

Release hygiene that stays in v1.6.0 without being a bet: TEST-388 (musl static
Linux builds, DD-18), TEST-389 (VEX), TEST-399 (compliance report per release).

## How this plan was checked

A planner pass drafted the bets from the North Star, the rivet state, the open
issues, the v1.5.4 notes and the baseline above. A second, independent pass saw
only the North Star and the draft and refuted every indicator claim as written,
several controls that could pass for the wrong reason, the "counts double"
weighting, the 0.80 threshold set before its baseline, and the size of Bet 3.
This version applies those findings.
